# GEO Agent 工作室

新增「搜索与询盘」：手动导入有来源的曝光、点击、线索、订单记录，按日期、渠道与来源筛选；将查询记录转为人工判断的机会，再填写内容简报并带入原有行动任务。未知不作零、重复不叠加、冲突不覆盖。见 [业务运营与测量指南](docs/business-measurement.md)。

开源的本地优先 SEO / GEO 运营工作台，采用 [MIT 许可证](LICENSE)。欢迎阅读 [贡献指南](CONTRIBUTING.md)。FastAPI + Next.js；采集、内容审核、发布核验与复测均保留证据和真实状态。

新增 SEO 检查：页面快照可识别跨页 canonical、多重/无效规范链接、语言对应冲突及子页面指向语言首页的可疑配置。Agent 计划会读取快照发现，并按客户场景、路线、费用、真实案例与资质依据组织优化建议。页面优化区标明需网站代码处理的发现；正文发布不能修改页面模板。参考站不视为自有品牌。使用方式与范围见 [参考网站驱动的优化说明](docs/reference-led-optimization.md)。

本地优先的 Agent-first GEO 工作流：提交业务目标 → Agent 读取官网并提出有据计划 → 人审核 → Agent 自动改稿 → 人审核并明确授权发布 → 后台自动更新既有 WordPress 资源、全文核验并安排维护。人工负责关键决定，不必逐页点击抓取、生成、发布、同步和核验。初始数据库为空，没有演示品牌、假活动或伪造效果。

## 本机安装与启动（Windows PowerShell）

需要 Node.js 22+、npm、Python 3.11+。从项目根目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
Set-Location frontend
npm install
Copy-Item .env.example .env.local
npm run build
Set-Location ..
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1
```

打开 http://127.0.0.1:3000 。脚本启动 127.0.0.1:8000 后端与 127.0.0.1:3000 前端，退出前端后停止其启动的后端。已有端口服务请先关闭，勿启动重复实例。生产构建后可传 `-Production`。亦可在两个终端手工启动：

```powershell
# 终端 A，项目根目录
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
# 终端 B
Set-Location frontend
npm run dev
```

默认 SQLite 文件用于零依赖本机运行；正式持久化可用 PostgreSQL，通过后端 `DATABASE_URL` 指定 SQLAlchemy URL。可运行 `docker compose up -d postgres`，项目 Compose 仅将数据库绑定到 `127.0.0.1:5433`，连接示例见根 `.env.example`（复制后仍需在终端设置环境变量；启动脚本不会自动加载根 .env）。启动时执行 Alembic 迁移。数据库需要备份，切换连接不会自动复制原数据库。完整字段见 [API 契约](docs/api-contract.md)，架构与能力边界见 [架构说明](docs/architecture.md)。

## 环境变量与安全边界

前端 `frontend/.env.local` 仅服务端读取：

```dotenv
GEO_API_URL=http://127.0.0.1:8000
GEO_BACKEND_TOKEN=
```

浏览器只请求同源 `/api/backend/*`，Next 服务端代理到后端 `/api/*`。服务 token 仅在代理请求中注入 Bearer，绝不使用 `NEXT_PUBLIC_*` 暴露 token。后端若启用 `GEO_BACKEND_TOKEN`，两侧必须相同。修改前端环境需重启 Next。

后端环境变量需在启动终端设置，例如 `$env:DATABASE_URL='...'`。可选采集配置 `RAZORMIND_URL`、`RAZORMIND_API_TOKEN`；可选模型配置 `OPENAI_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_MODEL`。不要把 secret 放入项目来源参数、表单、截图或提交记录。未配置模型时手工编辑和规则提及分析仍可用；显式请求模型返回不可用，不造假草稿或语义结果。

官网实际发布目前只支持 **WordPress REST 更新既有 page/post**。在后端启动终端配置 `WORDPRESS_URL`、`WORDPRESS_USERNAME`、`WORDPRESS_APPLICATION_PASSWORD`；使用专用、最小权限的应用密码，不在浏览器输入凭据。UI 发布配置仅填官网地址、`pages` / `posts` 和真实既有资源 ID，后端在提交前校验资源 ID / link 与登记页面一致。未配凭据时发布明确不可用，不模拟成功。其他站点可在外部人工发布，再保存明确的外部记录并进行正文核验。Razormind 仍用于原回答采集，不冒充当前不可用的动态官网发布适配。

页面/研究来源抓取默认限制内网和回环地址；仅受控验收或明确管理场景通过后端 `GEO_HTTP_ALLOWLIST` 设置精确 host:port。不要将宽泛内网访问权限开放给不受信任使用者。公开站点发布使用 HTTPS。详情见 [运营 API](docs/operations-api.md)。

默认仅监听回环地址，不开放公网。此系统不是多租户账户系统；若用户明确决定远程部署，必须另外配置认证反向代理、TLS、数据库访问策略，并严格限制访问。不要仅修改 `--host` 就暴露服务。

## Agent 主线：目标—进展—审核—成果

- **工作室**：选项目并提交目标；首次只需品牌、官网和目标。后台持久执行，页面刷新或关闭不会取消任务。真实状态包括排队、执行中、待审核、阻塞、失败、取消和完成；只展示执行摘要与依据，不展示内部思考。
- **待我审核**：先读完整计划或不可变改稿、目标 URL 和精确来源。网页事实候选仍须人工确认。批准计划自动继续改稿；仅批准内容不会外发；批准并授权发布会再次明确展示写入副作用。默认以本地审核人和按钮动作记录审计说明，仅退回或拒绝要求实际意见。反馈产生新提案，旧批准不能授权新稿。
- **成果与复盘**：区分已提交与完整可见正文已核验，显示真实维护时间。对比范围是“采集时页面正文”和“拟更新正文”，不是 CMS 完整结构差异；外站内容变化会阻止陈旧稿覆盖。核验不代表索引、AI 引用或 GEO 提升。
- **本轮范围与授权**：目标表单内渐进披露，默认最多两页、八次真实模型请求；采样仅在能力就绪时可申请，持续维护默认关闭。计划审核再次展示授权；持续维护到期自动读取官网并产生新待审计划，不自动发布。取消只阻止后续步骤，不能回滚已开始的外部写入。
- 缺模型时显示 **Agent 未就绪**，由服务器配置，不在浏览器输入密钥。缺 WordPress 配置仍可审核内容，但发布会阻塞；非 WordPress 使用高级工具中的外部人工发布与核验流程。详见 [Agent API 与安全边界](docs/agent-api.md)。

## 资料与高级工具

1. **运营工作台**：查看今日/本周真实任务、优先机会、待审核稿、已审待发布、待正文核验、失败发布和到期维护。队列按钮进入对应工作区，不用监控比例代替运营状态。
2. **机会与计划**：记录用户决策阶段、业务价值/适配、目标问题与页面、内容缺口、证据或明确假设及优先级。价值与适配是人工判断，不是搜索量。机会可创建或关联同一个 Action；运营任务填写负责人、到期时间、验收方法，受阻时填写原因。
3. **页面优化**：先在品牌资料登记官网，再登记需要优化的既有页面。显式抓取或明确人工导入 HTML，保存不可变快照、来源与真实可观察发现。查看发现的定位依据，创建优化任务；选择当前有效事实、目标问题及同 URL 内容条目，写优化简报和完整改稿，保存到现有内容版本库。模型模式需真实配置且可能计费，始终待人工审核；手工模式不依赖模型。
4. **内容与发布**：按不可变版本审核，记录审核人和说明。审核通过且事实仍有效才可显式授权 WordPress 更新。已发出、WordPress 响应成功、批准正文已核验是不同状态；HTTP 200 不代表页面内容正确，只有批准全文规范化正文匹配才能核验成功。同步仅只读检查资源状态，核验失败或提交不确定不会盲目重发。历史 `published_at` 仅展示为未核验的人工记录；旧直接登记发布接口已移除，当前人工外部记录也要通过审核与正文核验。
5. **研究与实验**：记录平台/渠道/模式/场景、来源、条件与局限；可显式抓取外部官方资料并保存不可变正文，引用必须精确。没有充分证据时保留假设或证据不足，不绘制算法权重。实验关联真实页面版本、基线/复测、对照组及观察窗口，冻结比较与分析依据；结论受样本、区间、发布时序与证据门禁约束。已有支持且经过审阅的研究/实验才能转为带边界的运营经验。流程验收不等于真实 GEO 提升。

**原有七区完整保留在侧栏“资料与高级工具”**：运营工作台、机会与计划、页面优化、内容与发布、研究与实验、品牌与事实、观测与验收。它们用于资料准备、异常处理与高级人工操作，不是 Agent 主线的必经搬运步骤。观测保留回答指标、问题采集、原文、诊断和复测；未知不当零，复测使用真实时间及已核验版本，不伪造因果或历史采样。

**维护**：Agent 完成本轮后持久化下一维护时间；明确申请并批准持续维护后，到期自动取证并生成新待审计划。高级工具仍可显式检查到期页面和事实。所有新稿仍需人工审核，发布仍需精确版本授权。

修正品牌别名后，可在回答区显式勾选“使用当前品牌别名重算（保留旧版本）”，再运行规则或模型分析。默认仍使用批次冻结别名；勾选只替换别名分析输入，不改原文或其他快照。新旧版本的完整分析记录保留输入依据。基线与复测分析别名/规则不同会标记不可比较，请使用一致口径后再解读差异。

## 编辑式运营界面

界面保持暖纸色、墨绿、朱砂、本地中文衬线字体与原创 SVG。主导航收敛为工作室、待我审核、成果与复盘；已有任务时收起新目标表单，优先阅读真实进展与待审产物，不再用六张空计数卡占据首页。

各区先展示品牌档案、事实出处、问题版本、任务验收与内容版本；点击明确的“展开操作”再新增或编辑，展开后显示“收起操作”。新建项目会滚动并聚焦表单，携诊断证据创建任务会自动展开并定位任务标题。键盘可操作原生披露与多选控件。

概览将带品牌与不带品牌分开，以提及率和真实样本基数为主，其他指标保留分子、分母与未知。回答区桌面为列表与原文阅读区，窄屏顺序排列；证据先显示已核验原文摘录与 Unicode 码点范围，完整 JSON 留在高级披露中。事实发现保留对应事实 ID 和说明，不重算或伪造证据位置。设计规格见 [视觉方向](docs/visual-direction.md)。

- “后端连接失败”：检查 8000 服务、`GEO_API_URL`、数据库与终端日志。
- 401：核对前后端 server-only token，勿把 token 填入浏览器表单。
