# GEO 工作台 · 视觉执行规格

目标：中文编辑式研究工作台，不是白卡 dashboard 换颜色。保留产品名 GEO 工作台；「观测档案」只作栏目/视觉题签，不改功能名。六区与所有真实操作保留。当前只改 frontend，禁止 seed、数据库变更、自动采集或自动模型调用。

## 2. 全站骨架与断点

- 1440：固定侧栏 204px，墨绿底，内边距 22px；右工作区 `min-width:0`，最大内容宽 1280px，左右 padding 36px。顶端 context 高约 72px，纸底+细底线；项目 selector 左、刷新/新建右。默认视口约 1120px 内容宽，不为留白牺牲主数据。
- 侧栏识别：大号 GEO（30px）+ 小号「工作台」；下方细线 +「观测档案 / OBSERVATION ARCHIVE」小题签。六行导航使用 01—06 序号，当前行浅纸字+细朱砂边或小方块，不用六个胖圆角按钮。底部两行「原文留存 / 证据可追溯」，不加虚构在线状态。
- 页面头：左 `0N / 栏目题签`、中文衬线 h1、单句说明；右可放真实记录量或极小图形，非每页巨大宣传 hero。头到工作内容 24px。模块以顶端细线与编号划分，减少层层 card > form > card。
- 768：侧栏取消 fixed，改全宽顶区；导航 3列×2行，文字全可见；context 在导航下，操作可换行。主区 padding 24px；双栏转单栏，但指标可 2列。
- 390：padding 18px；context 项目选择占整行，按钮第二行；导航 3列×2行，每项触达高 ≥44px。模块单列；指标首项整行、其余 2列；按钮栏换行。所有 grid 列 `minmax(0,1fr)`，长链接/标题 `overflow-wrap:anywhere`。原文与 JSON `white-space:pre-wrap;overflow-wrap:anywhere`；不要用 body overflow-x:hidden 隐藏布局问题。三列复测表应能自然压缩，不设固定 min-width。

## 3. 首屏：原创「观测轨道」印刷图形 + 实际指标

空库不自动打开完整建项表单。主区是一张开放式扉页，不是两张未知 KPI 卡：

- 左 7/12：小题签「GEO / 观测档案」，两行衬线主句「看见品牌，／在 AI 回答中的位置」；短说明「从真实问题与回答开始，建立可复核的品牌观察。」；实心主按钮「新建项目」，次说明「支持人工导入，无需采集账号」。点击按钮展开现有建项表单，保留全部字段与错误状态。中文为主，英文仅小号编辑标记；艺术感来自版式、材质、字体、构图，不来自渐变或动效，也不暗示排名保证。
- 右 5/12：原创 SVG 约 320×270，2—3 个墨绿细线偏心圆/椭圆、裁切边界、三条径向细线、朱砂小方印「GEO」，少量注册十字。圆环没有百分比、数据点、趋势箭头。图注明确「观测路径示意 · 非数据图表」。`aria-hidden` 图形，图注是普通文本。整体低墨量；不做动画、不像雷达 KPI。
- 下方贯穿细线+三段短说明：「01 品牌与事实」「02 问题与回答」「03 行动与复测」，各一句真实流程；不是新导航功能，不造六张大卡。手机右图缩至约 160px 高或简化，CTA 在图形前。
- 有项目无样本：用更紧凑 2/3 文字+1/3 图形区，说明「档案已建立，等待第一批真实回答」，给可执行入口「建立采集批次」/现有问题库入口，下列「完善事实→建立问题与批次→导入真实回答」步骤；不铺满十个未知指标。若服务返回空分组，或分组均为零样本，直接呈现观测起点；若分组有样本但分母未知，保留真实样本量与未知指标。
- 有数据：缩掉扉页，不让装饰挤占证据。筛选带下方按「不带品牌 / 带品牌」分别为两个横向研究分组；每组采用左侧 160px 分组标题+突出的真实样本基数，右侧品牌提及率主指标+其他4项较小条带/边注，以细竖线分隔而非五张等权卡。各指标保留可点击钻取与命中/分母/未知，明确推荐四状态保留在底部数据行。手机版分组说明在上，指标在下。禁止把不同 branded 分组混成一个漂亮总分。

## 4. 六区构图与默认顺序

1. **概览**：页题→一行筛选（批次较宽、平台/地区/意图等宽）→混合样本口径细提示→分组观测数据（上述非对称指标）→当前指标样本钻取。钻取作为题签「样本明细」的独立浅底证据区，命中/分母/未知三种列表清楚分开，原文入口保留。
2. **品牌与事实**：顶部左 2/3「品牌档案」只读展示名称/别名/官网/地区，右 1/3 档案注释/已存记录概况（只有从已加载真实数组得到的计数）；「编辑品牌」展开表单。下方事实库是主体宽列，竞品为较窄资料栏；有事实默认看到声明摘要+出处+有效期，不要求先展开才能知道来源。新增事实/竞品由模块标题同行按钮展开；编辑与删除保留在各条目详情中。手机事实在竞品前。
3. **问题库**（页说明明确含采集批次）：问题与版本列表是主体；每条默认显示题文、带品牌标签、版本、意图/地区/归档状态，详情内可编辑、版本记录、归档。模块头「新增问题」。其次「建立基线批次」独立一条主操作/展开区，不让完整建批字段默认挤走问题。采集源映射为辅助详情段，明确「人工导入可不配置」；source_id/JSON 属于次级详情，不占首屏。已有批次若采用父层已有 batches 展示真实名称/状态入口即可，不新增数据契约。
4. **回答明细**：批次选择+当前批次名/状态的紧凑 header，主操作「人工导入真实回答」展开；采集/同步与规则/模型分析归为两个清楚操作组，保留显式点击与当前别名重算 checkbox，不默认执行。已存回答列表必须在导入表单之前或其旁，桌面建议左 38% 列表、右 62% 原文与分析证据；现有结构不宜分栏时至少先列表后阅读区，避免表单占满首屏。选择态浅绿+左墨绿线；原文像研究摘录纸，行高 1.9、可长文本折行。有效性、任务完成、引用已知分开，不能合成一个「成功」。分析版本/原始 JSON/冻结条件渐进展开。
5. **诊断与行动**：保留一页三段「01 证据诊断」「02 行动任务」「03 内容版本」。诊断默认可见假设/回答依据/复核状态；生成诊断操作紧随批次选择。任务默认显示标题、负责人、状态、验收摘要，点击编辑；新增任务按钮展开。内容默认列表+真实版本数，展开后先看已有版本正文/发布记录，再编辑元信息、保存新版本/模型生成入口；发布登记不能伪装成系统发布。关键：点击「携此证据创建任务」必须主动打开新建任务披露区，再定位焦点，不只是滚到关闭的 details。
6. **效果复测**：先「两批对比」报告选择，再「创建匹配复测」展开操作；已选择复测后顶部是一行基线→复测的细线配对关系，明确条件匹配/可比较状态。主体两分组对照表：指标列+基线+复测，数值右对齐，百分点差采用带文字的结论行，不画伪趋势。警告置于表前；不确定性、分母/样本、对照组保持可展开。无复测时一段完整引导+建复测按钮；没有基线则说明前提，不给假的比较卡。

## 5. 组件与交互约束

- **展示先于编辑**：共享 Form 可以提供默认折叠的标题/触发按钮（新增、编辑都明确命名），表单打开后浅底+左细线，不能所有 Form 一概消失且没有入口。现有 `<details>` 内编辑无需再层层嵌套两次；顶层新增要折叠。用户触发的新项目/携证据任务须展开。已有版本内容不能藏在新版本大表单后。
- **列表**：用 16—20px 上下间距、细底线、状态小标签，而非每条厚卡。摘要文字可换行；ID 是小字辅助，业务标题主导。表格与条目不靠纯 hover 暴露操作。
- **按钮**：主色每个操作域最多一个；其余纸底描边或文本按钮。删除/拒绝朱砂字+边，危险语义文本明确。最小高度 40，触屏 44。所有真实操作路径保留，不能为了精简移除规则分析、模型分析、同步、版本、引用、对照组等。
- **披露**：native details/summary 或 button+aria-expanded 均可；清晰 +/−/箭头；键盘可打开。默认收起时要显示已存内容/条目摘要，不要整页只剩一串折叠标题。提交中禁用按钮、保留原始输入；错误在本表单 `role=alert`，成功 `role=status`，不自动丢失用户上下文。
- **状态**：空态=当前缺少什么+下一步，加载=细线占位/文字、不伪造数值；错误=朱砂细边浅底、保留服务端信息；未知=中性文字标签、不能借绿色暗示通过。成功/待复核/失败同时用文字，不能只靠颜色。
- **可访问性**：维持跳至工作区、真实 label、aria-current；焦点不被 sticky 顶部遮挡；正文对比度 ≥4.5:1；小字不使用低透明度。`prefers-reduced-motion:reduce` 下禁用过渡和平滑滚动；无必要动画。选择项目/切页状态保持现有合理边界。
