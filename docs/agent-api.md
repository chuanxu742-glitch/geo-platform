# Agent-first GEO API

All endpoints use `/api`, existing server authorization, JSON and `{detail}` errors. GET never starts network/model work. Models are real OpenAI-compatible HTTP calls; no model configuration means `ready:false`, start returns 503. This contract is the runtime/UI integration contract.

## Capabilities and worker

`GET /projects/{id}/agent-capabilities` returns `{ready:boolean,model_ready:boolean,website_ready:boolean,publishing_ready:boolean,sampling_ready:boolean,worker_ready:boolean,reasons:string[],publishing_reasons:string[],sampling_reasons:string[]}`. Configuration values and secrets are never returned. Publishing capability means server configuration plus an enabled project publisher exists, not that any target identity has been verified. Target-specific blockers appear on proposals/results.

`GET /agent-worker/health` returns `{running:boolean,poll_interval_seconds:2,lease_seconds:300,last_tick_at:string|null,reason:string}`. Single lifespan executor, durable claims; no browser dependency. Known transient database contention waits safely; unexpected scheduler/claim errors stop the worker, report `running:false` plus a safe exception type in `reason` and server logs. Capabilities become unready rather than claiming a live but stalled executor.

## Runs

`POST /projects/{id}/agent-runs` body `{goal:string,policy?:{max_pages?:1..3 (default 2),max_model_requests?:3..12 (default 8),review_interval_days?:1..365 (default 30),sample?:boolean (default false),continuous_maintenance?:boolean (default false)}}`; 201 returns Run. Only website-read/model planning is authorized by start. No publication or collection until explicit review authorization. Plan approval also grants the displayed opt-in continuing-maintenance policy; when due, the worker creates a linked new evidence/plan-review run, never implicitly republishes.

`GET /projects/{id}/agent-runs` returns Run[] newest first. `GET /agent-runs/{id}` returns Run with full `steps`, `proposals`, `approvals`, `current_proposal`, `outcomes`.

Run = `{id,project_id,goal,policy,status,phase,blocked_reason,created_at,updated_at,next_due:string|null,parent_run_id:number|null,steps:Step[],proposals:Proposal[],approvals:Approval[],current_proposal:Proposal|null,outcomes:Outcome[],observation:object}`. status = queued/running/awaiting_review/blocked/failed/cancelled/completed. phase is a human-readable execution phase key. All lists are present (empty when no data). `can_resume:boolean` indicates safe blocked recovery, never approval substitution. List is newest 100 runs.

Step = `{id,run_id,key,kind,status,summary,error,output,created_at,updated_at}`. Kinds also include `context`, `evidence`, `analysis`, `strategy_model`, and existing model/target-baseline stages; clients can render their readable `summary` without new labels. Status is running/completed/blocked. Output is execution evidence, never chain-of-thought. Completed outputs are immutable.

Proposal = `{id,run_id,kind,revision,status,summary,plan:object|null,drafts:Draft[],created_at}`. `id` is the immutable proposal Step ID; kind plan/drafts/publication_authorization; status pending/approved/request_changes/rejected/superseded derived from review history. A new model revision always creates a new proposal ID. `current_proposal` is the only reviewable object.

Plan = `{summary,targets:[{page_id,snapshot_id,target_url,title,question,branded:boolean,intent:string,decision_stage:"awareness"|"consideration"|"decision"|"retention",business_value:1..5,business_fit:1..5,judgment_basis:string,content_gap,hypothesis,priority,acceptance_method,instructions,expected_change,fact_ids:number[],fact_candidates:[{claim,source_url,snapshot_id,quote,start,end}],evidence:[{snapshot_id,url,quote,start,end}]}],sampling:{requested:boolean,reason:string},limitations:string[]}`. At most policy.max_pages targets, existing website pages only. Classification and subjective business judgments come from the real model with an explicit basis, not hardcoded middle scores or measured demand. `branded` must match project brand/aliases in the question locally. Candidate claim equals its exact quote but remains an unverified website statement until human plan approval. Approved candidates reuse an existing currently valid, unarchived same-project Fact only when claim AND source_url exactly match; IDs are deduplicated, never semantically merged. Existing facts are never overwritten.

Draft = `{page_id,target_url,content_id,content_version_id,title,before_text,after_text,body_hash,fact_ids,facts_snapshot,source_snapshot_id,source_url,expected_change,acceptance_method,generation,publisher_id:number|null,publishing_blocked_reason:string,wp_baseline:{site_url,resource,post_id,content_hash,modified_gmt:string|null,representation:"raw"|"rendered"}|null}`. `body_hash` SHA256 of exact UTF-8 approved after_text. Draft construction safely rejects active markup (script/iframe/forms/events/styles/embedded resources) and unsafe URL schemes locally before a proposal is reviewable. Frontend displays text, never executes draft HTML. Model inputs freeze facts, source snapshot and target/title; persistence rechecks them after model HTTP returns, preventing edited facts from being silently refrozen around an old generated body.

Outcome = `{page_id,target_url,content_version_id,publication_job_id:number|null,status,verified_at:string|null,next_review_at:string|null,action_id,reason,strategy_step_id:number|null}`. Only actual verified jobs are verified, not just POST success. `reason` reports the strategy/content change and real per-platform, branded/nonbranded comparison hit/denominator, semantic unknown counts, comparability and small-sample limitations. Empty groups are omitted; a sampled group with zero known denominator is unknown, not measured zero. Action done means content execution completed, not GEO goal achieved.

## Reviews: only necessary human decisions

`POST /agent-runs/{id}/approvals` body:

```json
{"proposal_id":12,"decision":"approve","feedback":"Reviewed exact sources and plan","reviewer":"Operator","allow_publish":false,"bindings":[]}
```

`decision` = approve / approve_only / approve_and_publish / request_changes / reject. `feedback` and `reviewer` nonblank required; approval buttons may supply a clear action-specific audit note and a locally remembered operator identity. Only rejection/changes need handwritten feedback. Plan only accepts approve/request_changes/reject. Plan approval approves displayed candidate facts and requested sampling/continuous maintenance, never website publication. Drafts accept approve_only/approve_and_publish/request_changes/reject. approve_only creates a publication_authorization proposal and performs no external write. Publication authorization accepts approve_and_publish/request_changes/reject. Any stale proposal, concurrent second approval, terminal/cancelled run returns 409. Reject and request_changes remain usable even when advanced edits invalidated the old body/title/facts; changed bindings cause fresh evidence and a new plan-review epoch.

`approve_and_publish` MUST set `allow_publish:true` and `bindings` exactly equal all displayed draft bindings `{page_id,content_version_id,target_url,body_hash,title}`. Other decisions MUST use `allow_publish:false` and empty bindings. This authorizes updating these exact already-existing WordPress resources with the displayed immutable body AND title, followed by public GET verification. Live Content.title/target edits invalidate old authorization. Draft preparation reads the exact WP resource and freezes its content hash/modified_gmt, not a dynamic full-page HTML hash. Before publication another GET must match identity/body/modified time; stale changes block without POST. WP GET→POST still has a short non-atomic concurrency window because this API has no CAS; no atomicity claim. Missing/mismatching publisher genuinely blocks. Non-WordPress uses the existing explicit external-publication record workflow, not fictitious Agent CMS support.

Approval response is updated Run. Approval audit = `{id,run_id,proposal_id,decision,feedback,reviewer,allow_publish,bindings,created_at}`. request_changes sends feedback and prior proposal to the real model, retains old proposal/approval/contentversion and awaits a fresh review.

`POST /agent-runs/{id}/cancel` no body: cancels future steps/continuing maintenance, not reversal of writes already begun. Returns Run. `POST /agent-runs/{id}/resume` no body: only safe blocked checkpoints, never repeats uncertain billable model calls or external submissions, never authorizes publishing. An awaiting publication_authorization with missing WP baseline may also refresh its baseline into a NEW consent proposal after configuration. If all approved drafts already have explicit external-publication records, resume can only verify them; it never issues a CMS update. A sample-authorized run without a prepublication baseline cannot retrofit one after external publication. Other unsafe/terminal/current-review cases return 409.

## Execution and bounded recovery

Start -> bounded frozen website/project/history context -> real model selection and plan -> human plan review -> original Question/Opportunity/Action/Content materialization -> **automatic approved baseline create/collect/durable sync/rules analyze** -> frozen strategy input -> **one real `strategy_model` refinement** -> immutable model ContentVersions consuming that strategy -> human draft review -> explicitly authorized original WordPress publisher -> read-only visible-body verification -> same-baseline retest/analyze/compare -> content-execution completion and maintenance. Baseline is completed before the first draft model request, never first collected after draft approval. Sampling off uses approved matching historical answers if present, otherwise explicit website-content hypothesis mode.

At most policy.max_pages selected site URLs plus home; no recursive crawl. All discovery/plan/strategy/draft HTTP requests reserve durable billable steps and consume max_model_requests; default 8 permits one discovery + one plan + one refinement + at most three drafts (6), leaving no hidden per-answer semantic calls. No automatic billable retries. Sampling uses one frozen existing Source and approved target questions (at most 3), 2-second polls, up to 300 seconds per wait and 300 total polls per phase. Pending waits automatically; unknown/confirmation/errors block. Resume reuses jobs/cursors. Rule Analysis recommendation/factual fields remain unknown: strategy semantics are separately attributed. Retest follows verified publication and remains descriptive, never causal.

Run+step unique keys, durable output checkpoints, a 300-second lease and 20-second heartbeat prevent duplicate workers. Interrupted model requests with no durable output are blocked as unknown, never automatically repeated. Existing PublicationJob reservation is reused; uncertain writes recover by GET only. Review rejection/cancellation stops subsequent writes; an already-started write cannot be undone. Due maintenance with explicit continuous consent creates one linked child run and fresh immutable snapshots/model plan for review; without consent no due-time model/network execution occurs. Untrusted page/model content cannot expand allowed origins, tool authority or secrets. No shell/browser/arbitrary HTTP write tools. Research sources remain the original explicit safe HTTP source mechanism; neither website prose nor platform documentation is treated as proof of algorithm control.

## Frozen evidence and strategy (additive, read-only)

No new endpoints, domain tables, approval decisions, or frontend changes are required. `steps[].output`, draft `generation`, and existing answer/batch APIs expose provenance. Context seed and completed evidence steps freeze their inputs before model use:

- Latest six same-project batches; exact project brand/region; at most twelve valid, complete answers, at most 12,000 Unicode characters each, observed within 180 days. Oversize answers are excluded, not truncated for an absence claim. Selection limits, exclusions, selected batches and limitations are stored. Each answer retains QuestionVersion, platform, observation time/provenance, batch mode, source configuration/modes, sampling parameters and region. Unknown channel stays unknown. No pooled cross-mode rankings.
- Historical latest Analysis ID/version is copied at initial context selection; `evidence_pool.analysis_runs` freezes each complete AnalysisRun once under its string ID, referenced by `answers[].analysis_run_id` (no duplicated per-answer input_snapshot). Fresh baseline uses the durable rules-analysis run ID. Diagnoses remain tied to those Analysis IDs. Later reanalysis does not rewrite strategy evidence; comparison with a changed baseline analysis is marked non-comparable.
- At most four reviewed supported research revisions and four rules, selected from the latest twenty each within a conservative 180-day reference window; verified source evidence and immutable current-matching revisions required. Refuted/inconclusive/unreviewed, changed rule sources and oversized source snapshots are excluded. Conditions and limitations stay attached. References are conditional hypotheses, not asserted applicability or algorithm control; no external claim becomes a brand Fact.

Plan targets add optional `answer_evidence:AnswerQuote[]` and `knowledge_references:KnowledgeReference[]`. Answer IDs/version/quote must belong to the supplied frozen pool. KnowledgeReference = `{kind:"research"|"rule",id,application:"conditional_hypothesis",conditions_to_verify}`; IDs must belong to that pool.

Strategy model payload is `{stage:"strategy",goal,project,approved_plan_id,approved_targets,snapshots,evidence_pool,baseline_batch_id}`. Strategy output = `{status:"ready"|"inconclusive"|"scope_change_required",mode:"answer_evidence"|"website_hypothesis",summary,targets,limitations}`. Each target = `{page_id,target_url,question_ids,fact_ids,judgments,instructions,expected_change,acceptance_method,knowledge_references?}` and each judgment = `{problem_type:"brand_absent"|"fact_mismatch"|"information_gap"|"recommendation"|"unknown",observation,cause_hypothesis,fact_ids,answer_evidence,website_evidence}`.

AnswerQuote = `{answer_id,analysis_id:number|null,analysis_version:number|null,question_version_id,batch_id,platform,observed_at,quote,start,end}`; Python Unicode start inclusive/end exclusive. Website evidence uses the existing `{snapshot_id,url,quote,start,end}`. Every judgment needs exact supporting evidence. Brand absence requires the entire valid answer and matching current brand/alias evidence checks; mentioning a brand does not establish recommendation. Fact mismatch requires approved Fact IDs valid at answer observation time, plus original answer quotation; it is a model judgment requiring subsequent draft review, not a rewritten Analysis result.

Ready strategies cover exactly approved pages/questions and only approved facts. Invalid evidence blocks before draft generation. Inconclusive blocks without pretending improvement; scope_change_required returns to a new plan proposal and requires human scope approval. Strategy cannot silently add URLs/facts/questions/publishers. Draft model instructions actually include the strategy target and citations. `ContentVersion.generation` freezes `strategy_step_id`, full strategy, target, evidence_pool, baseline_batch_id, approved_plan_id and evidence_mode. Existing proposal summary/expected_change/acceptance_method explain the concrete evidence and mark website-only hypotheses visibly.

Legacy runs reaching publication without a strategy and without any PublicationJob revoke the old publishing checkpoint, obtain evidence, regenerate immutable drafts and require fresh review; old proposals remain historical. If any external job exists, no new POST is allowed: all-job runs only recover existing jobs and report `legacy_observation_only`; partially submitted legacy runs block further publication. Missing pre-intervention evidence is never backfilled as a valid baseline.
