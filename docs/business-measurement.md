# 搜索、机会与内容运营

本轮将已有 SEO/GEO 优化流程接到业务观测：导入记录 → 人工选题 → 机会 → 内容简报 → 原有行动任务。不会根据查询词自动认定客户需求，也不会自动发布。

## 使用顺序

1. 选择项目，进入「搜索与询盘」。从可信报表整理下列八列，复制为 TSV（Tab 分隔，不是 CSV）。每次最多 1000 条，先核对预览，再确认导入。
2. 来源名称应固定到具体报表口径，例如「Search Console / 站点 A / 网页搜索 / 查询词维度」。不要将同一批数据换个来源名称再次导入，也不要混合页面合计和查询明细后相加。
3. 用渠道、来源与起止日期筛选。空指标表示未知，只有实际观察到零才填 0。若筛选记录任一行缺某指标，该指标合计显示未知；已知覆盖数另行展示。
4. 在「资料与高级工具 → 机会与计划」选择查询记录，人工判断是否包含品牌。确认会创建或复用文字与品牌分类相同的问题，但机会仍是未保存的草稿。
5. 补充决策阶段、内容缺口、价值、适配和优先级，再保存机会。导入记录及其来源保留在待验证假设中，不冒充已审核业务事实。
6. 在机会卡填写适用条件、步骤、费用、可核验来源、真实案例和验收方式。带入任务表单后，确认负责人、到期时间、页面和关联问题，再保存。简报保存在现有任务的验收方法中；未知内容标为待补充。

## 导入字段与 API

表头顺序固定：

```text
date\tpage_url\tchannel\tquery\timpressions\tclicks\tleads\torders
```

上面的 `\t` 表示实际 Tab 字符。日期为有效的 `YYYY-MM-DD`；URL 为完整 HTTP(S) 地址且不得包含凭据；渠道为 `seo`、`geo` 或 `other`；查询可空。指标为 0 到 9007199254740991 的整数或空值，不能使用小数、逗号或单位。单元格不支持 Tab 或换行。

- `POST /api/projects/{id}/measurements/import`：`{source_label, rows: [{date, page_url, channel, query, impressions, clicks, leads, orders}]}`。JSON 中未知值用 `null`。返回 `imported`、`duplicates` 和 `source_label`。
- `GET /api/projects/{id}/measurements`：返回 `rows`、`summary`、`limitations`。沿用已有服务鉴权，不增加公开访问入口。
- 同项目、来源、日期、页面、渠道、查询组成唯一记录。完全重复会跳过；同一身份不同指标返回 409，整批不写入，不静默覆盖。当前没有更正或删除测量记录界面，发现原始报表错误应先备份并由维护者处理，不能换来源名绕过去重。

## 边界与验收

当前是人工导入版本，没有自动接入 Search Console、CRM 或分析平台。来源与渠道由操作者声明，不代表独立核验或因果归因。不同来源可能重叠，GEO 标签也不证明 AI 引用带来了订单。

单次导入上限 1000 条；列表 API 暂无分页，前端记录表仅展示筛选后前 200 条，合计仍使用全部筛选记录。大规模长期数据接入需先补充服务端分页与聚合。不得导入密码、密钥或客户敏感信息。

本地隔离验收使用明确标注的合成数据：曝光 20、点击 2、线索未知、订单 0；重复导入显示新增 0 / 重复 1；查询词创建问题与机会后，内容简报成功保存至行动任务，问题与机会关联均由 API 复核。验收不涉及客户库、真实模型生成、官网发布或效果提升。
